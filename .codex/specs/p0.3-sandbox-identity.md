# P0.3 & P0.5: Sandbox Identity and Negative Controls

## Goal
Secure the Docker sandbox lifecycle to prevent cross-contamination between targets, and create a full negative control fixture.

## Requirements
1. **Target Verification (`main.py`)**: 
   - `ensure_sandbox_running` must inspect the currently running `cipherloop-sandbox` container.
   - It must verify the container's bound volume matches the absolute path of `target_dir`.
   - If the paths do not match, it must forcefully kill the stale container and provision a new one.
2. **Negative Control Fixture (`fixtures/safe/`)**:
   - Create a new application in `fixtures/safe/app.py`.
   - The app must contain a `subprocess.run` call, but the input must be hardcoded or strictly sanitized (no `request.args` flow).
3. **End-to-End Test (`tests/test_e2e_safe.py`)**:
   - Create a test that runs the LangGraph loop against the `fixtures/safe/` directory.
   - Assert that `compressed_findings` might find the sink, but `verified_findings` is empty.
   - Assert that the final report string states no high-confidence vulnerabilities were found.

## Definition of Done
The CLI never reuses a sandbox bound to the wrong directory, and the end-to-end test passes, proving CipherLoop can safely conclude "No vulnerabilities found."
