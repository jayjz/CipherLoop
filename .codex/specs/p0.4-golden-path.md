# P0.4: The Golden Path (Positive Control)

## Goal
Establish a deterministic end-to-end integration test that proves the LangGraph orchestration successfully identifies, validates, and reports a true positive vulnerability.

## Requirements
1. **End-to-End Vulnerable Test (`tests/test_e2e_vulnerable.py`)**:
   - Create a test mirroring `test_e2e_safe.py`, but targeting `fixtures/toy`.
   - Mock the LLM responses to simulate a successful tool discovery (e.g., the local model outputs a Semgrep finding pointing to `fixtures/toy/app.py:11`).
   - Run the graph invocation.
   - Assert that `compressed_findings` contains the raw signal.
   - Assert that `verified_findings` contains exactly 1 item with `status == "VERIFIED"`.
   - Assert that the verified finding correctly maps the source (`request.args.get`) and the sink (`subprocess.run`).
   - Assert that the final synthesized report mentions the verified vulnerability.

## Definition of Done
The test suite contains both positive (`test_e2e_vulnerable.py`) and negative (`test_e2e_safe.py`) controls that run entirely offline without requiring a live Docker daemon or Anthropic API key.
